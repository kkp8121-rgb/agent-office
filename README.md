# 에이전트 사무실

이 PC 에서 돌아가는 Claude Code · Codex 세션을 픽셀 사무실의 층으로 보여 주는 로컬 화면입니다.
세션 하나가 한 층, 직원(서브 에이전트·워크플로 에이전트)은 그 층의 캐릭터입니다. 서버는 `127.0.0.1` 에서만 열리고, 외부 패키지 설치는 필요 없습니다(Node.js 만).

용어: 층 = Claude Code·Codex 세션 하나 · 팀장 = 그 세션의 메인 에이전트 · 직원 = 서브 에이전트와 워크플로 에이전트 · 프로젝트 = 워크플로 실행 · 업무 일지 = 활동 기록 · 사장님 = 건물 전체를 보는 사용자.

## 켜기

- `agent-office.cmd` 를 더블클릭합니다. 서버가 없으면 최소화된 서버 창을 띄우고 브라우저를 엽니다. 이미 떠 있으면 브라우저 화면만 엽니다(서버 중복 실행 없음).
- 바탕화면 바로가기 만들기(한 번만):
  `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\make-shortcut.ps1`
  다른 폴더에 만들려면 `-Destination <폴더>` 를 붙입니다.

## 위쪽 줄: 층 전환 · 순환 · 활발한 곳 따라가기 · 전체 화면

화면 맨 위 줄에 층마다 숫자 단추(1 = 로비, 2, 3 … = 그 위의 층)가 있습니다(색은 층별 안내의 색, 마우스를 올리면 층 이름). 숫자를 누르면 그 층만 화면에 꽉 차게 보이고, 같은 숫자를 다시 누르거나 「전체」 를 누르면 모든 층을 쌓아서 보는 화면으로 돌아옵니다. 보던 층이 끝나거나 숨겨지면 다음 층으로 넘어가고, 남은 층이 없으면 쌓아서 보는 화면으로 돌아갑니다. 보이지 않는 층은 시계와 걷기를 멈추고 상태만 따라갑니다.

- 순환: 켜면 지금 보던 층(없으면 첫 층)부터 `config.json` 의 `ui.rotate.seconds`(기본 15초)마다 다음 층으로 돌아가며 보여 줍니다. 숫자나 「전체」 를 누르면 꺼집니다. 작은 창이 열려 있으면 작은 창에서 돌아갑니다.
- 활발한 곳 따라가기: 켜면 가장 활발한 층(최근 `ui.follow.windowSeconds` 초의 업무 일지·상태 변화와 일하는 캐릭터 수로 계산)을 바로 한 층 보기로 보여 주고, 다른 층이 확실히 더 활발해지면(`switchMargin`·`switchRatio`, 보던 층은 최소 `minDwellSeconds` 초 유지) 그 층으로 옮겨 갑니다. 모두 조용하면 그대로 있습니다. 순환과는 동시에 켤 수 없고, 숫자나 「전체」 를 누르면 꺼지며, 전체 화면과 작은 창에서도 똑같이 동작합니다(전체 화면을 따로 켜 주지는 않습니다).
- 다크 모드: 위 줄의 「다크 모드」 단추로 어두운 화면과 밝은 화면을 바꿉니다. 처음에는 운영체제 설정을 따르고, 직접 고른 값은 이 브라우저에 기억됩니다(저장이 막혀 있어도 동작). 작은 창에도 같이 적용되고, 방 그림은 층마다 정적인 어두운 막(`ui.dark.roomDim`)으로 어둡게 하며 창밖은 밤으로 바뀝니다(`ui.dark.nightWindows`). 그림 속 방 바깥 배경(크림색·초록 등)은 `scene.json` 의 `outline`(방 윤곽 다각형) 바깥을 페이지 배경색으로 덮어 어둡게 하며(정적 덮개, 밝은 모드에서는 투명), 잠든 직원의 zZ 는 어두운 모드에서 밝은 보라색에 어두운 테두리로 바뀝니다. 날씨 효과는 없습니다.
- 머리 위 작은 말풍선(「…」): 한 층에서 가장 최근에 말한 `ui.bubbleFullMax`(3)명만 전체 말풍선을 두고, 나머지는 접힌 말풍선 「…」 로 보입니다. 「…」 에 마우스를 올리면 전체 문장이 작게 뜹니다(캐릭터 본체의 툴팁에도 같은 문장).
- 전체 화면: 브라우저 전체 화면으로 바꿉니다(Esc 로 끝냄). 전체 화면 동안 층별 안내는 자동으로 숨고, 끝나면 본인이 정해 둔 상태로 돌아옵니다.
- 층별 안내 숨기기: 오른쪽 층별 안내를 접어 층이 가로 전체를 쓰게 합니다. 선택은 이 브라우저에 기억됩니다. 창 너비가 1100px 보다 좁을 때 한 층 보기에서는 층별 안내가 자동으로 숨어(아래로 밀려 스크롤이 생기지 않게) 전체 보기로 돌아오면 다시 나옵니다.
- 「작은 창」 과 「끄기」 는 이 줄 오른쪽으로 옮겼습니다.

## 1층 로비 · 현황판

1층은 로비입니다. 다른 층은 2층부터 시작합니다(서버가 `floorNo` 를 1 늘려 보내므로 층 표지, 숫자 단추, 층별 안내 줄, 단추 설명이 모두 따라갑니다). `config.json` 의 `lobby.enabled` 를 `false` 로 하면 로비 없이 예전처럼 1층부터입니다.

- 로비로 가기: 위 줄 맨 앞의 금색 「1」 단추. 다시 누르면 「전체」 로 돌아옵니다. 「전체」 로 쌓아 보는 화면에는 로비가 들어가지 않아(같은 직원이 두 번 보이지 않게) 「활발한 곳 따라가기」 도 로비를 고르지 않습니다. 순환은 로비 → 2층 → 3층 … → 로비 순으로 돕니다. 작은 창에서는 현황판 부분만 잘라 보여 줍니다.
- 직원: 모든 층의 팀장·직원(직원은 서브 에이전트와 워크플로 에이전트, 한 프로젝트 안의 직원은 「프로젝트 직원」)이 자기 얼굴·이름·상태 그대로 로비 책상 뒤에 서 있습니다(책상은 모두 정면 직선이고, 얼굴이 가려지지 않도록 서 있는 정면 그림을 쓰며 의자 등받이가 어깨 옆으로 보입니다. 로비에서는 접는 말풍선 「...」 을 보이지 않고, 말을 한 직후의 글 말풍선은 맨 뒷줄에만 뜹니다. 졸음 직원은 흐려지는 대신 회색빛으로 바뀌고 zZ 는 머리 옆에 놓입니다). 같은 층 사람끼리 이웃해 서고, 이미 자리를 잡은 사람은 자리를 바꾸지 않습니다. 이름표 앞에는 층 번호가 층 색 칩으로 붙어서 이름이 같은 직원도 어느 층 사람인지 바로 보이고, 팀장은 이름 앞에 작은 ★ 가 붙습니다(밝은 화면·어두운 화면 같음). 이미 일을 마친 채로 처음 보인 직원은 책상을 차지하지 않습니다. 책상 40개가 차면 오른쪽 홀과 소파 쪽에 12명까지 서 있고, 그보다 많으면 「+n명은 현황판에서」 표가 뜹니다(현황판에는 전부 나옵니다). 로비의 캐릭터는 걷거나 잡히지 않고(움직임 애니메이션 없음), 누르면 그 층으로 갑니다.
- 정면 벽 현황판(실제 글자, 화면을 키워도 선명. 양옆 두 판은 바깥쪽 끝이 더 높게 그려져 오목하게 보이고, 글자는 `web/board.mjs` 의 `quadFrame` 이 만든 원근 변환 `matrix3d` 로 화면 네 모서리에 얹혀 바깥쪽으로 갈수록 커집니다): 가운데는 「직원 현황판」(이름 · 층 · 구분 · 상태 · 지금 하는 일 · 근무 시간 · 보고, 한 쪽에 들어가는 만큼씩 `ui.lobby.pageSeconds`(6초)마다 다음 쪽, 줄을 누르면 그 층으로, 「상태」 와 「지금 하는 일」 은 같은 말을 되풀이하지 않아서 「생각 중…」 같은 상태 말풍선은 「-」 로 둡니다), 왼쪽은 「사무실 지수」(층별 활동 지수의 합, 1분 전과 비교한 ▲ 빨강 / ▼ 파랑)와 근무 중 · 대기 · 보고 · 진행 중 프로젝트 · 실패 · 졸음 숫자, 오른쪽은 「층별 활동 지수」(층 · 제목 · 지수 · 변화, 줄을 누르면 그 층으로), 각 화면 아래 띠는 「업무 일지」 최신 3건입니다. 활동 지수는 「활발한 곳 따라가기」 와 같은 계산입니다. 「보고」 는 사무실이 켜진 뒤 일을 마친 직원 수, 「실패 (10분)」 은 모든 층에서 최근 10분(`ui.lobby.failMinutes`) 안에 본 실패한 도구 결과 수(시간이 지나면 줄어들고, 0보다 클 때만 빨강), 근무 시간은 팀장은 층이 생긴 때부터, 직원은 처음 발견된 때부터입니다.
- 다크 모드에서도 현황판은 어두운 막 위에 그려져 그대로 빛납니다.
- 자원: 로비를 보는 동안에도 requestAnimationFrame · 캔버스 · 폴링이 없고 무한 반복 애니메이션이 하나도 돌지 않습니다. 시계와 쪽 넘김은 타이머 하나(`clockTimers`, 작은 창을 따라감)이며 로비가 안 보이면 타이머도 그림 작업도 없습니다(상태만 저장). 숫자와 문구는 `config.json` 의 `ui.lobby`, 현황판 크기 상수는 `web/app.js` 위쪽(`LED_*`)에 있습니다.
- 개인정보는 그대로입니다. 현황판에 나오는 것은 이름, 역할, 층 제목, 말풍선·업무 일지에 이미 나오는 문장, 숫자, 시각뿐이며 서버가 새로 보내는 값은 숫자·참거짓뿐입니다(`startedAt`, 실패 시각 목록 `failAt`, 직원의 `enteredAt`, `wf`).

## 작은 창(PiP)

화면 오른쪽 아래 「작은 창」 단추를 누르면 층만 보이는 항상 위 작은 창이 뜹니다(크롬·엣지 116 이상만, 다른 브라우저에서는 단추가 안 보입니다). 크기는 `config.json` 의 `ui.pip`. 원래 탭을 닫으면 작은 창도 닫히고, 작은 창을 닫거나 단추를 다시 누르면 층이 탭으로 돌아옵니다.

## 캐릭터 잡기

캐릭터를 누른 채 끌면(또는 0.3초 이상 누르고 있으면) 들어 올려 옮길 수 있고, 놓으면 떨어져 어지러워한 뒤 자기 자리로 걸어갑니다. 화면 놀이일 뿐 실제 작업에는 영향이 없고 저장되지 않습니다. 숫자는 `config.json` 의 `ui.grab`.

### 콕 찌르기 · 던지기 · 보고 · 하이파이브

- 콕 찌르기: 캐릭터를 짧게 누르면 말풍선으로 반응하고, 짧은 간격으로 계속 누르면 반응이 커집니다(「네?」 → 「왜요?」 → 「일하는 중이라니까요!」 → 머리에서 김). 잠깐 쉬면 처음으로 돌아갑니다. 팀장을 누르면 팀장 말투로 반응합니다. 직원 말풍선의 「팀장님, …」 은 층의 팀장에게 하는 말이고, 건물 전체를 보는 사용자는 「사장님」입니다. 간격·표시 시간은 `ui.poke`.
- 던지기: 들고 빠르게 끌다가 놓으면 그 방향으로 포물선을 그리며 날아가 방 안쪽 벽에 튕기고, 길게 어지러워한 뒤 자기 자리로 걸어갑니다. 날아가는 길은 놓는 순간 한 번 계산합니다(`ui.throw`: 최소 속도, 거리, 튕김 횟수 등).
- 팀장에게 보고: 직원을 팀장 가까이에 놓으면 팀장 앞에 서서 지금 하고 있는 일(말풍선에 보이는 그 글자)을 보고하고, 팀장이 답한 뒤 자리로 돌아갑니다. 하는 일이 없으면 쉬는 중이라고 말합니다. 팀장을 직원 가까이에 놓으면 팀장이 한마디 합니다.
- 하이파이브: 직원을 다른 직원 가까이에 놓으면 둘이 뛰며 「짝!」 하고 각자 하던 곳으로 돌아갑니다. 반경은 `ui.play`.
- 진행 중 직원이 끝나거나 자리가 바뀌면(실제 상태가 항상 우선) 장면은 바로 끝납니다. 모두 화면 놀이일 뿐 실제 작업·업무 일지·저장에는 영향이 없고, 작은 창에서도 똑같이 됩니다.
- 말풍선 대사는 전부 `config.json` 의 `ui.lines`(상황별 목록)에 있습니다. 상황마다 8줄 이상이고 직전과 같은 줄은 연달아 나오지 않습니다. 새로 온 직원의 인사는 시간대(아침·낮·저녁·밤)에 따라 달라지고, 쉬는 자리에서 만나면 잡담도 합니다. 직원의 실제 말풍선이 새것이면 잡담은 나오지 않습니다.

### 화이트보드 할 일 · 프로젝트 회의 · 실패 표정

- 화이트보드: 방마다 있는 화이트보드에 그 층(팀장)의 실제 할 일 목록이 적힙니다. 제목은 「할 일 3/7」, 진행 중인 항목은 ▶ 와 노란 줄, 끝난 항목은 ✓ 와 줄긋기, 남은 항목은 ☐ 입니다. 보드가 작아 다 보이지 않으면 진행 중인 항목 둘레만 보여 줍니다(최소 3개). 목록이 바뀔 때만 다시 그리고, 비어 있으면 깨끗한 보드입니다. 보드를 누르면 그 층의 전체 목록이 큰 글씨로 열리고, Esc · 다른 곳 클릭 · 보드를 다시 누르면 닫힙니다. 항목 글자는 서버가 20자로 줄인 것 그대로입니다(Claude 의 TodoWrite · TaskCreate/TaskUpdate, Codex 의 update_plan).
- 할 일 목록을 쓰지 않는 층은 보드가 차례로 이렇게 채워집니다. ① 할 일 목록 ② 돌고 있는 프로젝트의 단계(「단계 2/4」, 지나간 단계 ✓ · 지금 단계 ▶ · 남은 단계 ☐ — 단계 이름은 실행 중인 프로젝트 스크립트의 `meta.phases` 제목을 코드를 실행하지 않고 읽은 것이고, 스크립트에 없으면 지금까지 시작된 단계만 보입니다) ③ 그 층의 직원들(「직원 3명」, 일하는 중 ▶ · 보고를 마친 직원 ✓ · 기다리는 직원 ☐, 항목은 직원이 맡은 일 설명) ④ 층 제목. Codex 층은 update_plan → 직원 → 제목 순서입니다. 어느 경우든 보드를 누르면 전체가 크게 열립니다.
- 프로젝트 회의: 프로젝트가 다음 단계로 넘어가면 그 층의 직원이 화이트보드 앞 회의 자리(`scene.json` 의 `meeting.spots`)로 걸어와 모이고, 팀장이 「다음은 「검토」 단계!」 처럼 단계 이름을 말합니다. `ui.meeting.seconds`(기본 5초) 뒤 모두 자리로 돌아갑니다. 자리보다 사람이 많으면 나머지는 그대로 있고, 회의 중 새 단계가 오면 팀장 말이 바뀌며 시간이 다시 시작합니다. 회의는 단계가 실제로 바뀌는 순간에만 열리고(이미 지난 단계, 화면에 없는 층은 건너뜀) 대기열에 쌓지 않습니다.
- 실패 표정: 명령이나 시험이 실패하면 그 캐릭터 머리 옆에 땀방울(1번째), 연달아 실패하면 먹구름(2번째부터)이 `ui.fail.seconds`(기본 6초) 동안 뜹니다. 연달아 `ui.fail.patStreak`(기본 3)번 실패하면 팀장이 걸어와 토닥여 주고 캐릭터가 대답합니다(층마다 `ui.fail.patCooldownSeconds` 기본 60초에 한 번). 팀장 본인이 실패하면 먹구름만 뜹니다.
- 숫자는 `config.json` 의 `ui.meeting` · `ui.fail`, 대사는 `ui.lines` 의 `meetingBoss` · `patBoss` · `patReply` 입니다. 모두 화면 놀이일 뿐 저장되지 않고, 작은 창에서도 똑같이 됩니다. `?debug=ambient` 에서는 `__ambient.signal('phase', {sessionId, phase})` · `__ambient.signal('fail', {sessionId, agent, streak})` 로 서버 없이 같은 장면을 띄울 수 있습니다.

### 계절 장식 · 창밖 시간 · 간식 주기

- 계절 장식: 날짜에 맞춰 방마다 장식이 놓입니다. 핼러윈(10월 24일~31일)은 호박과 박쥐, 크리스마스(12월 18일~26일)는 트리·선물·리스, 설날(음력 1월 1일 2일 전~2일 후, 한국 음력 달력으로 계산)은 복주머니·청사초롱입니다. 기간 밖에는 아무것도 없습니다. 장식은 `scene.json` 의 `seasonal` 자리(바닥 4 · 벽 3 · 책상 4)에만, `assets/seasonal/items.json` 의 그림 크기가 자리의 `max` 에 들어갈 때만 놓이고 걷는 길에는 놓이지 않습니다. 방마다 늘 같은 모양이며, 바닥·책상 장식은 캐릭터와 같은 순서로 앞뒤가 정해집니다. 날짜는 `ui.season`.
- 창밖 시간: 창밖 풍경(아래 「창밖 풍경」)이 실제 시각에 따라 낮 그림 · 노을(낮 그림 위에 정적 그라데이션 한 겹) · 밤 그림으로 바뀌고 어두운 모드에서는 밤입니다. `scene.json` 의 `windows`(유리 부분)에는 노을·밤에 얇은 색 한 겹만 더합니다(`view` 가 없는 방은 예전처럼 낮에는 그대로, 노을은 따뜻한 주황, 밤은 짙은 파랑). 시각 기준: 노을(`ui.daylight.sunset`, 17~19시)은 따뜻한 주황, 밤(`ui.daylight.night`, 19~6시)은 짙은 파랑입니다. 방의 나머지는 그대로입니다. 날짜와 시각이 바뀌는 순간까지 타이머 하나만 걸어 두고(주기적으로 확인하지 않음), 숨겨진 탭에서 돌아오면 다시 읽습니다.
- 확인용 주소: `?season=halloween|christmas|lunar|none` 과 `?time=day|sunset|night` 로 날짜·시각을 덮어씁니다(둘 다 따로).
- 간식: 위쪽 줄의 커피 · 도넛 · 쿠키 · 생선을 캐릭터에게 끌어다 놓으면 손에 간식이 나타나 「냠냠」 한 뒤 「힘이 난다!」 와 함께 `ui.snack.sparkleMs`(기본 2초) 동안 반짝입니다. 캐릭터마다 `ui.snack.cooldownSeconds`(기본 10초) 동안은 「배불러요」 류 대사만 하고 아무 일도 없습니다. 생선은 치즈에게만 맞고(먹고 쓰다듬을 때처럼 하트), 사람에게 생선이나 치즈에게 다른 간식을 주면 웃긴 거절 대사만 합니다. 캐릭터 밖에 놓으면 취소됩니다. 작은 창(PiP)에 층이 있는 동안은 창 사이로 끌 수 없어 간식 단추가 꺼지고 안내가 뜹니다. 대사는 `ui.lines` 의 `snackEat` `snackDone` `snackFull` `snackNoFish` `snackNoCat` `catSnackDone`. 화면 놀이일 뿐 저장되지 않습니다.

### 사무실 고양이 「치즈」

사무실 전체에 고양이 한 마리가 있고, 보이는 층 중 한 곳에서 돌아다닙니다(층이 없으면 없음). 걸어 다니다가 쉬는 자리(창가·책장·화분 등)에 앉거나, 일하는 직원의 책상 옆에 앉거나, 소파 자리에서 잡니다. 몇 분마다 문으로 나가 다른 층에서 나타납니다.

- 쓰다듬기: 고양이를 짧게 누르면 하트와 「골골…」이 나오고, 빠르게 계속 누르면 점점 커집니다(하트 1 → 2 → 3 → 5개).
- 들기·던지기: 직원과 같은 방식으로 들 수 있고(「냐앙!」), 놓거나 던지면 네 발로 착지(별 없음)한 뒤 다시 돌아다닙니다. 고양이는 팀장 보고·하이파이브 장면에 끼지 않습니다.
- 책상 옆에 앉으면 직원이 가끔 한마디 합니다. 숫자는 `config.json` 의 `ui.cat`, 대사는 `ui.lines` 의 `cat*` 항목입니다. 그림은 `assets\sprites\cat-*.png`(`art\catuild.py`).
- 타이머는 고양이 전체에 최대 하나이고, 걷는 동안만 CSS 애니메이션이 돌아갑니다. 화면이 가려지면 멈추고 작은 창에서도 같이 움직입니다. `?debug=ambient` 에서는 10배 빨라지고 `__ambient.cat()` · `__ambient.catDo('sleep'|'spot'|'desk'|'stroll'|'leave')` 를 쓸 수 있습니다.

### 걷는 다리

걸을 때 캐릭터의 다리가 엇갈립니다. 새 그림 없이, 같은 그림의 엉덩이 아래를 왼쪽·오른쪽 반쪽으로 한 번 더 그려 0.4초에 두 걸음씩 서로 자리를 바꾸고(벌어짐 ↔ 교차) 몸은 1px 오르내립니다. 서 있거나 앉아 있을 때는 아무것도 돌지 않습니다. 그림마다 다리가 시작되는 줄과 갈라지는 열은 `ui.walk.hips`(그림 높이·너비의 %)에 있고, 표에 없는 새 그림은 `hipDefault` 를 씁니다. 확인용 점검표: `python art\walk\sheet.py <출력.png>`.

## 끄기

화면의 「끄기」 단추를 누르거나, 최소화된 서버 창(제목 「에이전트 사무실 서버」)을 닫습니다.

## 숨기기

층별 안내에서 숨기면 그 층의 캐릭터, 층별 안내 줄, 업무 일지가 모두 사라집니다. 다시 보이기 단추는 없습니다.

- Claude: 그 층을 다시 실행할 때(껐다 켜기, 이어서 실행)까지 안 보입니다.
- Codex: 쉬고 있던 층이 다시 활동을 시작할 때까지 안 보입니다.
- 사무실을 껐다 켜도 숨김은 유지됩니다(`data\` 폴더에 저장).

## 이름 바꾸기

층별 안내의 ✎ 단추 또는 층 표지 더블클릭 → Enter 저장, Esc 취소. 비우면 자동 이름(층 제목, 없으면 작업 폴더 이름)으로 돌아갑니다. 최대 30자이고, 사무실을 다시 켜도 유지됩니다.

## 캐릭터 이름 · 역할 바꾸기

`config.json` 의 `roles` 표에서 `name`(이름)과 `role`(역할)을 고치고 사무실을 다시 켭니다.

- 팀장(층마다 한 명)은 `leads` 표의 5명(유나·하나·수아·윤슬·다인)이 돌아가며 맡습니다. 지금 화면에 있는 층에서 가장 적게 쓰인 팀장이 새 층에 배정되고, 숨기거나 떠난 층의 팀장은 곧 풀립니다. 그림은 `assets\sprites\<key>.png`, 앉은 그림은 `<key>-sit.png` 입니다.
- 같은 층에서는 직원마다 얼굴과 이름이 다릅니다. 종류의 대표 캐릭터(`roles` 표)를 그 층에서 아무도 쓰고 있지 않으면 그 캐릭터를, 이미 쓰고 있으면 아직 안 쓰인 캐릭터를 돌아가며 받습니다. 후보는 `roles` 표의 17명과 `extras` 표의 12명(지유·나연·소율·예나·다솜·유리·채이·도희·이솔·아라·연우·민서, 이름은 Claude·Codex 층 공통)이며 팀장 5명은 빌려 주지 않습니다. 29명이 모두 쓰이고 있을 때만 `서진+1` 처럼 번호가 붙습니다. 직원은 층에 있는 동안 얼굴과 이름을 그대로 가지고, 떠나면 그 얼굴이 풀립니다.
- 빌린 얼굴이어도 역할 칸은 실제 종류(예: `선임`)로 표시됩니다. `roles` 표에 없는 종류(예: `general-purpose`)는 역할 칸에 종류 이름(없으면 `지원`)이 표시됩니다.
- 새 캐릭터를 더하려면 `assets\sprites\<key>.png`·`<key>-sit.png` 를 만들고 `extras` 표와 `ui.walk.hips` 에 한 줄씩 적습니다.

## 그림 다시 뽑기

Codex 의 imagegen 으로 그림을 만든 뒤 `art\snap.py` 로 격자에 맞춥니다. 프롬프트는 `art\prompts.json`(캐릭터), `art\scenes\<방>.json`(방), `art\sit\prompts.json`(앉은 자세)에 있습니다. 결과는 `assets\` 아래에 둡니다. 옛 한 장짜리 배경 `art\floors\*.png` 는 방을 다시 뽑을 때 쓰는 참고 그림이고 화면에는 쓰지 않습니다.

### 방(장면) 그림 — 껍데기 + 오브젝트

층 그림은 모두 장면입니다. `designOrder` 의 방마다 `assets\scenes\<방>\scene.json` 이 있어야 하고, 없거나 형식이 틀리면 서버가 시작하지 않습니다. 방(`assets\scenes\<방>\`)은 한 장짜리 배경이 아니라 빈 방 껍데기(`shell.png`), 가구 모음(`objects.png`), 필요하면 앞 덮개(`front.png`), 배치 데이터(`scene.json`)로 이루어집니다. 프롬프트와 목표 크기는 방마다 `art\scenes\<방>.json` 에 있습니다. 원본(Codex 결과)은 저장소 밖 작업 폴더에 두고 `--work` 또는 환경변수 `AGENT_OFFICE_ART_WORK` 로 알려 줍니다.

1. 껍데기: `codex exec` 로 `art\floors\<방>.png` 를 편집해 가구만 지운 방을 받고(러그·벽에 붙은 책장은 유지), `python art\snap.py shell <입력> assets\scenes\<방>\shell.png --size 1024x512` 로 줄입니다.
2. 가구 시트: 마젠타(`#FF00FF`) 배경에 물건 6개 안팎을 두 줄로 뽑고, `python art\snap.py sheet <시트.png> <작업폴더>\s1 --rows 2` 로 조각(`piece-<번호>.png`)을 나눕니다.
3. 아틀라스: `art\scenes\<방>.json` 의 `kinds` 에 조각과 목표 폭·높이를 적고 `python art\atlas.py <방>` 을 실행하면 `objects.png` 가 만들어지고 `scene.json` 의 `kinds[*].rect` 만 갱신됩니다.
4. 앞 덮개가 필요하면 `scene.json` 의 `frontMask` 를 적고 `python art\front.py <방>` 을 실행합니다.
5. 배치(`anchor`·`footprint`·자리·`spots`)는 `scene.json` 에 직접 적고 `node scripts\check-scenes.mjs <방>` 로 검사한 뒤, `python art\scene_sheet.py <방>` 으로 점검표(`art\scenes-check\<방>.png`)를 만들어 눈으로 확인합니다.
6. 모든 방 검사: `node scripts\check-scenes.mjs`(방 이름을 주면 그 방만). `npm test` 도 출하된 장면을 같은 검사기로 돌립니다.
7. 윤곽: `python art\backdrop.py <방>` 이 `shell.png` 의 바깥 배경을 가장자리에서부터 채워 방 윤곽을 찾고(2~3픽셀 안쪽으로 줄여 테두리 번짐까지 덮음) `scene.json` 의 `outline`(장면 안의 점 3개 이상, 선택 항목)을 적습니다. 어두운 모드에서만 윤곽 바깥을 덮습니다. 껍데기를 새로 만들면 다시 실행합니다(`--check` 는 쓰지 않고 검사만, `--inset`·`--eps`·`--tol` 조절).

### 창밖 풍경 (`view`)

방마다 창밖은 창 하나하나에 붙인 작은 그림이 아니라 방 전체에 걸친 한 장의 풍경(`assets\scenes\<방>\view-day.png`, `view-night.png`)입니다. 그림은 장면 좌표에 고정돼 있어 이웃한 창은 같은 풍경의 이웃한 부분을 보여 주고, 수평선 높이가 방 전체에서 하나(`view.horizon`)이며(높은 창은 하늘, 낮은 창은 가까운 나무·꽃), 멀리는 작고 흐리게 · 가까이는 크고 선명하게 그렸습니다. 방마다 바깥 주제는 그대로입니다(도시 · 호수 산골 · 소나무 숲 · 정원).

- 층: 방 그림(`shell.png`)은 RGBA 이고 유리 자리가 투명(구멍)입니다. 풍경은 그 아래 배경 겹으로 깔리고(`.stage.viewed`, style.css) 날씨·유리 색(`.sky`)·가구·캐릭터·방 어둡게 하는 막(`.stage::after`)은 전과 같은 자리에서 그 위에 얹힙니다. 낮/노을/밤은 `data-light` 만으로 고르므로 자바스크립트도 타이머도 필터도 없고, 가려진 층은 그림을 받아 오지 않습니다.
- `scene.json` 의 `view`: `{"origin":[x,y],"size":[w,h],"day":"view-day.png","night":"view-night.png","horizon":y}`(선택). 상자는 장면 안에 있고 모든 `windows` 다각형을 덮어야 하며, 그림 크기는 `size` 와 같아야 합니다(`node scripts\check-scenes.mjs`).
- 풍경 그림 만들기: Codex 로 방마다 낮 1장 · 밤 1장(`art\prompts.json` 의 `views`, 호출은 `python art\extras\gen_view.py <방> day|night`)을 받아 `python art\view.py <방> day|night <원본.png> <수평선 비율>` 로 줄입니다(LANCZOS, 수평선 안개, 팔레트 정리). 방별 상자·수평선은 view.py 안 `ROOMS` 에 있습니다. 눈높이 느낌은 수평선(먼 풍경 아래쪽 끝)이 창 위쪽에 오고 먼 산·건물 윤곽 위의 하늘이 유리 높이의 약 1/3 이하가 되도록 원본을 아래쪽으로 잘라 `--zoom` 으로 키운 것입니다(밤 그림은 낮 그림과 같은 줄에 오도록 원본끼리 어긋난 만큼 `수평선 비율`을 낮 값에서 빼서 따로 넘깁니다).
- 밤 그림이 밋밋하면 `--gamma G --sat S` 로 팔레트 정리 뒤에 밝기·채도를 올립니다(픽셀 ** G, G<1 이 더 밝음, 그다음 채도 ×S). 라운지 밤 그림: `python artiew.py lounge night <lounge-night-eye2.png> 0.4938941176470588 --zoom 1 --hy 130 --gamma 0.78 --sat 1.25` (원본의 수평선 비율 0.4938941176470588 = 낮 0.4852941176470588 − 밤 어긋남 −0.0086, 같은 원본이면 커밋된 `view-night.png` 와 픽셀까지 같습니다).
- 유리 구멍 내기: `python art\glass.py <방>` 이 `art\glass.json` 의 방식(`poly` 다각형 · `colour` 다각형에서 창틀 색 빼기 · `flood` 온실처럼 색으로 유리를 찾고 매달린 화분은 빼기)으로 `shell.png` 의 유리를 투명하게 만듭니다. 구멍 밑에는 옛 그림의 RGB 가 남아 있고(알파를 무시하는 도구는 옛 풍경을 봄), 가장자리 1~2픽셀은 옛 유리색 번짐을 창틀 색으로 지웁니다. 이 가장자리 정리 때문에 이미 구멍 낸 `shell.png` 에 다시 돌리면 같은 결과가 나오지 않으니 한 번만 적용합니다. 온실 `shell.png` 는 fc99fbe 판 shell 에 지금 `glass.json` 을 한 번 적용한 결과라, 다시 만들 때는 `git restore --source fc99fbe -- assets/scenes/greenhouse/shell.png` 로 그 판을 꺼낸 뒤 `python art\glass.py greenhouse` 를 한 번 돌립니다. `art\scene_sheet.py` 는 낮 풍경을 깔고 점검표를 만듭니다.
- 구멍 때문에 `shell.png` 만 보면 유리가 비어 있습니다. 풍경 파일이 없거나 안 읽히면 유리 자리에 하늘색(`#8fc9ee`)이 보입니다.

### 앉은 그림

일할 때 자리에 앉은 캐릭터는 `assets\sprites\<키>-sit.png`(높이 `sitHeight` = 50px, 오른쪽을 보는 대각선 정면)를 씁니다. 파일이 없는 키는 서 있는 그림 그대로 자리에 서서 일합니다. 다시 뽑으려면 `art\sit\prompts.json` 의 시트별 문장으로 Codex 에서 시트를 받고, `python art\snap.py sheet <시트.png> <작업폴더>` 로 조각을 나눈 뒤 `python art\snap.py sprite <조각> assets\sprites\<키>-sit.png --height 50 --colors 20` 로 줄입니다. `art\sit\contact-sit.png` 가 점검표입니다.

## 걷기 · 생활 움직임

캐릭터는 가구를 돌아 걷고(내비 격자 + 최단 경로), 책상·화분 앞뒤에 맞게 그려집니다. 일하는 캐릭터는 가끔 몸짓을 하고, 한가한 캐릭터는 방 안의 지점(창가·커피·책장·소파 등)에 다녀옵니다. 서버가 정한 자리·상태가 언제나 이깁니다.

- 화면 주소 끝에 `?debug=nav` 를 붙이면 층마다 걷기 격자, 오브젝트 윤곽, 모든 자리·지점, 캐릭터가 마지막에 걸은 경로를 겹쳐 그립니다.
- `?debug=ambient` 는 생활 움직임을 10배 빠르게 하고 `window.__ambient.timers()`(층별 타이머 수)를 노출합니다.
- 끄기: `config.json` 의 `ui.ambient.enabled` 를 `false` 로 바꿉니다. 주기·머무는 시간·동시에 나가 있는 최대 인원(`maxAway`)도 같은 블록에서 조절합니다. 걷기·깊이 숫자는 `nav`·`depth` 블록입니다.

## 창밖 날씨 · 설정

창(`scene.json` 의 `windows`) 안에 날씨가 그려집니다: 흐림(천천히 흐르는 구름) · 안개(정지한 옅은 안개) · 비 · 눈 · 뇌우(비 + 11초에 한 번 아주 약하고 느린 번쩍임. 깜빡이는 효과는 없습니다) · 맑음(아무것도 안 그림). 창 유리의 낮·노을·밤 색 위, 가구와 캐릭터 아래에 얹히고, 밤에는 더 어두운 색과 구름 그림으로 바뀝니다. 움직임은 CSS 키프레임(transform·opacity)뿐이고 초당 몇 장씩 끊어서(`steps()`) 그려 자바스크립트 타이머가 없고, 보이는 층에서만 돌며(가려진 층은 그리지 않음), 숨은 탭에서는 멈추고, 작은 창(PiP)에서도 같습니다. 시스템의 「동작 줄이기」 설정이면 움직이지 않는 그림만 남고 번쩍임은 없습니다. 그림은 `art/weather/build_wx.py` 가 `assets/fx/wx-*.png`(합쳐서 3KB 안팎)로 만듭니다.

**설정 단추**(위쪽 줄 「설정」): 날씨를 고릅니다. 자동(실제 날씨, 기본) · 맑음 · 흐림 · 안개 · 비 · 눈 · 뇌우 · 날씨 끄기. 고정해서 고르면 실제 날씨와 상관없이 그 날씨가 보이고, 「날씨 끄기」는 모든 날씨 효과를 없앱니다. 선택은 이 브라우저의 localStorage(`agent-office.weather`)에 기억하며(막혀 있어도 동작하고 그 창에서만 유지), 서버로는 보내지 않습니다. 패널에는 「지금 서울: 비」처럼 실제 날씨(알 수 없음이거나 config 에서 꺼져 있으면 그렇게)와 출처 줄 「날씨 정보: Open-Meteo.com」이 같이 보입니다. Esc 나 바깥 클릭으로 닫히고 포커스가 단추로 돌아옵니다. 문구는 `ui.weather`.

**실제 날씨와 바깥으로 나가는 연결 한 가지**: 이 앱에서 인터넷으로 나가는 요청은 이것 하나뿐입니다.
- 어디로: `https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.978&current=weather_code` (Open-Meteo, 가입·키 없음). 나가는 것은 `config.json` 의 `weather` 에 적은 도시 좌표와 위의 고정 값뿐이고 층·이름·ID·경로·기기 정보는 담기지 않습니다. 다만 인터넷 요청이 늘 그렇듯 이 PC 의 공인 IP 는 그 서버에 보입니다.
- 언제: 화면이 하나라도 연결돼 있는 동안만, `refreshMinutes`(30분)마다 한 번. 첫 화면이 연결될 때 저장된 값이 30분보다 오래됐으면 즉시 한 번 묻고, 마지막 화면이 닫히면 타이머가 사라집니다. 가려진 탭은 연결을 끊으므로 요청도 멈춥니다. 실패하면 10초 안에 포기하고 5 → 15 → 30분 간격으로 다시 시도하며, 그동안 마지막 값을 쓰다가 `staleMinutes`(180분)가 지나면 「알 수 없음」(날씨 효과 없음)으로 표시합니다. 서버 로그에는 상태가 바뀔 때만 한 줄 남습니다.
- 화면으로: 종류(맑음·흐림·안개·비·눈·뇌우·알 수 없음), 도시 이름, 시각만 보내고, 종류가 바뀔 때만 보냅니다. 응답 원문은 넘기지 않습니다. 코드 → 종류: 0·1 맑음, 2·3 흐림, 45·48 안개, 51~57·61~67·80~82 비(이슬비·어는 비·소나기 포함), 71~75·77·85·86 눈, 95·96·97·99 뇌우, 그 외 알 수 없음(Open-Meteo 의 WMO 날씨 코드 표).
- 도시 바꾸기: `config.json` 의 `weather.city`(화면에 보이는 이름)와 `weather.latitude` · `weather.longitude` 를 고치고 서버를 다시 켭니다.
- 바깥 요청 끄기: `config.json` 의 `weather.enabled` 를 `false` 로 하고 서버를 다시 켭니다. 그러면 요청도 타이머도 전혀 없고(패널은 「꺼져 있습니다」), 설정에서 날씨를 직접 골라 보는 것은 그대로 됩니다.
- 출처: 날씨 정보 Open-Meteo.com. 확인용으로 서버를 띄울 때 `AGENT_OFFICE_WEATHER_URL=http://127.0.0.1:포트` 를 주면 그 로컬 가짜 서버로만 묻습니다(시험용).
- 시험: `npm test` 는 `tests/helpers/no-outbound.mjs` 를 먼저 읽어 루프백이 아닌 곳으로의 연결을 막으므로, config 에 날씨가 켜져 있어도 시험이 바깥으로 요청하는 일은 없습니다.

## 개인정보

화면과 업무 일지에는 도구 이름, Bash 설명과 명령의 첫 단어, 파일 이름(경로 전체 아님), 직원이 맡은 일 설명, 층 제목, 작업 폴더 이름, 할 일 항목(20자까지), 프로젝트 단계 이름(20자까지), 시각만 나갑니다. 사용자 메시지, 답변, thinking, 도구 결과, 파일 내용, 명령 전체, 검색어는 읽어도 내보내지 않습니다. 서버는 `127.0.0.1` 에서만 받고, 다른 웹페이지에서 오는 요청은 거절합니다. 바깥으로 나가는 요청은 창밖 날씨 하나뿐이며(좌표만, `weather.enabled` 로 끌 수 있음) 위 「창밖 날씨 · 설정」에 적혀 있습니다.

데스크톱 앱에서 연 층의 제목은 Claude 앱은 대화 기록의 `custom-title`, Codex 앱과 터미널은 `~/.codex/session_index.jsonl` 의 `thread_name` 에서 옵니다(둘 다 층 제목이라 위 목록에 이미 들어 있습니다). Codex 기록 첫 줄의 계정 식별자·기본 지침은 읽지 않으며 어디에도 나가지 않습니다. 칩의 「Claude 앱」·「Codex 앱」은 기록에 적힌 시작 위치 이름만 보고 정합니다.

층 위의 「보고 N」은 일을 끝내고 결과를 넘긴 직원의 수이며 사무실이 켜진 뒤로 센 값입니다. 중간에 멈춘 직원은 세지 않습니다.

## 문제 해결

- 「포트 47800 을 다른 프로그램이 쓰고 있습니다」 → `config.json` 의 `port` 를 다른 번호로 바꿉니다(환경변수 `AGENT_OFFICE_PORT` 로 임시 지정도 가능).
- 서버가 멈춘 채 47800 포트를 잡고 있으면: `netstat -ano | findstr 47800` 으로 PID 를 찾고, 그 PID 하나만 종료합니다(프로그램 이름으로 한꺼번에 끄지 마세요).
- 「Node.js 가 필요합니다」 → https://nodejs.org 에서 설치합니다.
- 숨김·이름 기록 폴더(`data\`)는 환경변수 `AGENT_OFFICE_DATA_DIR` 로 다른 곳으로 옮길 수 있습니다. 시험·데모 서버는 꼭 지정해서 실제 기록과 섞이지 않게 하세요.
- 디버깅용: 환경변수 `AGENT_OFFICE_NO_BROWSER=1` 이면 런처가 브라우저를 열지 않습니다.
- 시험: `npm test`
