## 5. 화면

### 5.1 건물과 층
- 화면 왼쪽(넓은 쪽)은 **건물 단면**이다. 층이 위아래로 쌓이고, 층마다 픽셀 사무실 그림 한 장이 깔린다.
- **사무실은 더 넓고, 디자인이 다양하고, 디테일하게 (사용자 요청 2026-10-28)**: 시안 배경보다 넓은 가로형 방(책상 10~12개, 통로 여유)으로, 서로 다른 인테리어의 배경을 **4종** 뽑아 층마다 돌아가며 쓴다(예: 기본 개발실 · 카페형 라운지 · 서재형 · 식물 많은 온실형 — 종류는 그림 작업에서 정한다). 소품·조명·창밖 풍경 등 디테일을 시안보다 늘린다. 한 층의 디자인은 그 층이 생길 때 정해지고 바뀌지 않는다. (종류 수·예시는 내 판단)
- 층 순서: 세션 시작 시각 기준, **새 세션이 위층**. 보는 도중에 층 순서가 바뀌지 않는다. (내 판단)
- 층 표지: `3F · <세션 제목>` + 작업 폴더 이름 + 상태(작업 중 / 입력 대기). 세션 제목은 기록의 `aiTitle`, 없으면 작업 폴더 이름.
- 층이 많으면 세로 스크롤. 층 높이를 줄여 한 화면에 더 보이게 하는 기능은 1차에서 하지 않는다.

### 5.2 층 안
- **화이트보드**(참고 화면 왼쪽 위 판처럼): 그 세션의 제목과, 워크플로가 돌고 있으면 `워크플로 이름 · 단계 i/n`.
- **책상 10~12개**(배경마다 다름): 서브에이전트가 생기면 빈 책상에 앉는다. 배경마다 자리 좌표 표를 따로 둔다.
- **팀장 자리**(앞쪽 보고함 탁자): 메인 세션 자신이 캐릭터로 서 있다. 메인 세션의 현재 행동이 말풍선에 뜬다. (내 판단 — 참고 화면의 PD 자리)
- **보고함**: 일을 끝낸 서브에이전트가 와서 서류를 놓는다. 오늘 받은 보고 수가 배지로 붙는다(참고 화면의 「PD 보고 1」).
- **소파**: 입력을 기다리는 캐릭터가 쉬는 곳(선택적 연출).

### 5.3 오른쪽 기록 칸 (참고 화면 형식)
- 한 줄 = 작은 캐릭터 아이콘 + **이름**(굵게) + 시각(오른쪽) + 아래 1~3줄 설명.
- 설명 형식: `<단계 또는 할 일> · <설명> · <지금 동작>`. 예: `코드 리뷰 · review:bugs · PostController.cs 읽는 중`.
- 맨 위에 **세션 목록**(층 색 점 + 이름 + 서브에이전트·워크플로 수 + ✎ 이름 바꾸기 + 숨김 단추). 숨긴 세션은 목록에도 나오지 않는다.
- 위쪽 「전체 기록 ↗」 → 별도 페이지: 같은 형식, 세션·캐릭터로 걸러 보기.
- 기록이 너무 빨리 쌓이지 않게: 시작·끝·명령 실행(Bash)·파일 수정(Edit/Write)·위임(Agent/Workflow)·스킬은 한 줄씩, 읽기·검색(Read/Grep/Glob)이 연달아 오면 한 줄로 묶는다(「파일 12개 살펴봄」). 세부 규칙은 빌더 몫.

### 5.4 숨기기 (강제 숨김 — 사용자 확정 2026-10-28)
- 세션 단위. 숨기면 그 층, 그 세션의 서브에이전트·워크플로 캐릭터, 세션 목록의 그 줄, 그 기록 줄(메인 화면·전체 기록 모두)이 함께 **완전히** 사라진다. 화면에 「다시 보이기」 단추는 없다.
- 다시 나타나는 때: **그 Claude 세션을 다시 실행했을 때만**(껐다 켜기, 이어서 실행 — 즉 그 세션의 프로세스가 바뀌었을 때). 숨김은 「세션 id + 그때의 프로세스(pid·시작 시각)」 에 묶인다.
- 사무실 프로그램을 껐다 켜도 숨김은 유지된다(서버 쪽 파일에 저장).
- 숨길 때 실수 방지용으로 「이 세션을 다시 실행할 때까지 안 보입니다」 확인을 한 번 받는다. (내 판단)
- 숨긴 프로세스가 끝나면 그 숨김 기록은 저절로 지워진다.

### 5.5 세션 이름 바꾸기 (사용자 확정 2026-10-28)
- 세션 목록의 ✎ 단추나 층 표지를 더블클릭하면 그 자리에서 이름을 고칠 수 있다. Enter 저장, Esc 취소, 비우면 자동 이름(세션 제목 → 작업 폴더 이름)으로 돌아간다.
- 바꾼 이름은 층 표지·화이트보드·세션 목록·기록 칸 어디서나 쓰인다.
- 이름은 세션 id 기준으로 서버 쪽 파일에 저장해서, 사무실을 다시 켜도, 그 세션을 이어서 실행해도 유지된다. 최대 30자. (내 판단)

### 6.2 그림
- 역할마다 다른 SD 픽셀 미소녀 한 장(정면 3/4, 오른쪽을 봄, 투명 배경). 팀장 포함 위 표의 이름 수만큼.

## 8. 개인정보

- 화면·기록·전체 기록 페이지로 내보내도 되는 것: 도구 이름, Bash `description`, Bash 명령의 첫 단어, 파일 **이름**(경로 전체 아님), 에이전트 `description`, 스킬 이름, 워크플로 이름·단계·라벨, 세션 제목(`aiTitle`), 작업 폴더 이름, 시각.
- 절대 내보내지 않는 것: 사용자 메시지 본문, 모델 답변 본문, thinking, 도구 결과, 파일 내용, Bash 명령 전체, 검색어, `queue-operation` 내용(사용자 입력이 들어 있음), Codex 기록의 계정 id.
- 서버는 `Host` 헤더가 `127.0.0.1:<포트>`/`localhost:<포트>` 가 아니면 거절하고, 다른 출처(Origin)의 요청을 받지 않으며 CORS 헤더를 붙이지 않는다(다른 웹페이지가 몰래 읽어 가는 것 차단).
- 서버가 이 규칙을 지킨다(브라우저로 원문을 보내고 화면에서 거르는 방식 금지).

## 9. 실행 방식 (내 판단)

- 브라우저 페이지 단독으로는 이 PC 의 기록 파일을 읽을 수 없으므로, **Node.js 로 만든 작은 로컬 서버 + 브라우저 화면**으로 만든다. npm 패키지 설치 없이 Node 기본 기능만 쓴다.
- 서버가 기록 파일을 지켜보다 바뀐 내용을 브라우저로 밀어 준다(SSE).
- `에이전트 사무실.cmd`(또는 `agent-office.cmd`) 더블클릭 → 서버가 안 떠 있으면 띄우고 → 기본 브라우저로 화면을 연다. 이미 떠 있으면 화면만 연다(서버 중복 실행 금지).
- 바탕화면 바로가기를 만들어 주는 것까지 1차에 포함.
- 서버를 끄는 방법이 분명해야 한다(화면의 「끄기」 단추 또는 런처 창 닫기). 프로세스 이름으로 끄는 방식은 쓰지 않는다(사용자 규칙: 자기가 띄운 PID 만).

## 10. 성공 기준

1. 런처 더블클릭 후 몇 초 안에 브라우저에 건물이 뜨고, 지금 살아 있는 세션 수만큼 층이 보인다.
2. 아무 세션에서 서브에이전트를 띄우면 2초 안팎에 그 층에 캐릭터가 들어와 앉고, 말풍선이 그 에이전트의 실제 최근 행동을 보여 준다.
3. 서브에이전트가 끝나면 보고함으로 가서 점프하고 사라지며, 기록 칸에 남는다.
4. 워크플로를 돌리면 에이전트들이 각자 캐릭터로 나타나고 화이트보드에 단계가 뜬다.
5. 세션을 숨기면 그 층·캐릭터·목록 줄·기록이 사라지고, 서버를 다시 켜도 숨김이 유지되며, 그 세션을 다시 실행하면 다시 나타난다. 세션 이름을 바꾸면 모든 곳에 반영되고 서버를 다시 켜도 유지된다.
6. 기록 칸·전체 기록 어디에도 §8 의 금지 항목이 나오지 않는다(테스트로 확인).
7. 켜 둔 채 가만히 있을 때 CPU 사용이 거의 없다(목표: 1~2% 이하), 100MB 기록 파일이 있어도 시작이 느려지지 않는다.

## 13. 아직 확인 안 된 사실 (빌더가 실측으로 확인할 것)

- `sessions\<pid>.json` 의 `status` 값 전체와 뜻(busy/shell 외), 세션이 끝나면 이 파일이 지워지는지.
- 워크플로 실행 요약 json 이 진행 중에도 바뀌는지(아니면 `journal.jsonl` 과 에이전트 기록으로 진행 상황을 잡아야 한다).
- 포그라운드(백그라운드가 아닌) 서브에이전트의 기록 위치와 `finished` 표시 여부.
- 서브에이전트가 또 서브에이전트를 부를 때(`spawnDepth` > 1) 폴더 구조 — 1차에서는 같은 층에 함께 앉히면 된다.
- 비정상 종료한 서브에이전트를 「응답 없음」으로 볼 기준 시간.
