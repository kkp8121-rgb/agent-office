## 1. 의도와 이유

### 1.1 사용자 요청 (원문)
> 「책상 위에 캐릭터가 서 있는데 이거 입체적인 구조로 만들어야 겠다 레이어 방식으로」
> 「지금 이미지를 사용할 수 없는게 책상 등 다른 오브젝트들에도 레이어를 도입하고 네비메시를 깔아야해」

### 1.2 지금 무엇이 문제인가
- 층마다 배경이 **그림 한 장**(`assets/floors/<design>.png`)이고 책상·의자·화분·소파가 전부 그 안에 칠해져 있다.
- 캐릭터(64px 그림 한 장, 이동·늘이기·뒤집기만)는 그 위에 얹힌다. 그래서 자리 좌표가 책상 위에 찍히면 **책상 위에 서 있는 것처럼** 보이고, 걸을 때는 **가구를 뚫고 직선**으로 간다(`walkTo` 는 직선 한 번).
- 앞뒤 순서는 캐릭터끼리만 발 y 로 맞추고(`zIndex = y`), 가구와의 앞뒤는 표현할 방법이 없다.
- ⇒ 지금 그림은 **그대로는 쓸 수 없다**. 가구를 그림에서 떼어 각자 층(레이어)으로 만들고, 걸을 수 있는 바닥을 따로 정의해야 한다. **(사용자 결정: 모든 오브젝트에 레이어 + 내비메시)**

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 모든 가구·소품이 자기 레이어이고, 캐릭터와 **앞뒤가 맞게** 그려진다. 책상 뒤에 선 캐릭터는 책상에 다리가 가려지고, 화분 앞을 지나는 캐릭터는 화분 위에 그려진다.
- 캐릭터는 가구를 **돌아서** 걷는다(벽·가구를 뚫지 않는다).
- 네 방(studio2·lounge·library·greenhouse)의 지금 분위기(넓은 가로형, 다양한 인테리어, 소품 많음)를 유지한다.
- 자원 예산 유지: 화면을 연 상태 평균 한 코어 2% 이하(지금 실측 0.16%), 탭이 가려지면 멈춤.

**비목표 (이번에 하지 않음)**
- 걷기 프레임 그림. ~~앉은 자세~~ → 2026-10-28 사용자 요청으로 **앉은 자세 그림 1장을 추가한다**(§17). 그 밖의 프레임 애니메이션은 계속 하지 않는다.
- 캐릭터끼리 서로 피해 걷기. 지나갈 때 겹쳐도 된다. 서 있을 때 겹치지 않는 것만 보장한다(§6.5). **(관제 판단)**
- 가구 움직이기, 화면에서 배치 편집하기, 층 사이 이동 연출.

**실패 조건 (동작해도 실패)**
- 캐릭터가 책상·탁자 위에 서 있는 것처럼 보인다, 또는 가구를 뚫고 걷는다.
- 이름표·말풍선이 가구에 가려진다. 문틈·보고함 줄에 선 캐릭터가 앞 덮개(`front.png`)에 가려진다.
- 자리·보고함·팀장 자리·대기점 중 하나라도 문에서 걸어갈 수 없다.
- 가구 둘레에 배경색 테두리(키잉 잔여물)가 보인다, 또는 방이 지금보다 밋밋해진다.
- 매 프레임 그리기 루프(`requestAnimationFrame`)·캔버스 애니메이션이 생긴다, CPU 예산을 넘는다.

## 4. 장면 데이터 모델

### 4.1 어디에 두나 (관제 판단)
- 디자인마다 폴더 하나: `assets/scenes/<design>/`
  - `scene.json` — 장면 데이터(이 절)
  - `shell.png` — 빈 방 껍데기: 바닥, 뒤·옆 벽, 벽에 붙은 장식(창문·액자·화이트보드·벽등·문·매달린 화분), 러그(§4.7), **벽에 딱 붙은 책장·장(평면으로 그대로 둠, §4.7)**. **캐릭터를 절대 가리지 않는 것만** 들어간다.
  - `front.png` — 앞쪽 벽·난간·턱(방 앞 가장자리) 덮개. 껍데기와 같은 크기의 투명 PNG. 없으면 생략.
  - `objects.png` — 그 방의 오브젝트 그림 모음(아틀라스). 투명 배경.
- `config.json` 에는 `designOrder`(그대로)와 새 숫자 블록(§4.8)만 둔다. 기존 `layouts` 는 이전 뒤 삭제.
- 서버가 시작할 때 `scene.json` 을 읽어 형식 검사(§10.1의 1단계)를 하고, `/api/ui` 로 화면에 넘긴다(§7.2).

### 4.2 `scene.json` 최상위 필드

| 필드 | 뜻 |
|---|---|
| `version` | `1` |
| `design` | 폴더 이름과 같아야 함 |
| `size` | `[폭, 높이]` 방 픽셀 크기 = **지금 그림 크기 그대로**. studio2 `[1024, 512]`, lounge·library·greenhouse `[1024, 576]`. 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 그림 시험에서 `-i` 편집이 원본 비율(2:1)을 그대로 지켰으므로 studio2 를 576 으로 바꾸지 않는다. 방마다 높이가 달라도 되고 `fitFloors` 는 폭만 본다 |
| `shell`, `front`, `atlas` | 위 세 그림 파일 이름 |
| `board` | `[x, y, w, h]` 화이트보드 글자 칸(지금과 같은 뜻) |

| `walkable` | 걸을 수 있는 바닥 다각형 목록 `[[[x,y],…], …]`(합집합). 바닥 윤곽을 따라 꼭짓점 몇 개로 |
| `blocked` | 오브젝트와 무관하게 막을 다각형 목록(예: 바닥 위 계단 턱, 벽에 붙은 껍데기 책장 앞 띠). 없으면 `[]` |

| `door` | `{ "at":[x,y], "face":"left|right" }` — 새 캐릭터가 나타나는 점(걸을 수 있어야 함) |

### 4.3 `kinds` — 종류마다 한 번만 정의
```
"desk": {
  "rect": [x, y, w, h],          // objects.png 안의 그림 위치
  "anchor": [ax, ay],            // 그림 안에서 '바닥에 닿는 앞쪽 가운데' 점
  "footprint": [[dx,dy], …],     // 바닥에 닿는 넓이, anchor 기준 상대 좌표 다각형
  "blocks": true,                // 길을 막는가
  "depth": "auto",               // §5 — auto | overhead | floor
  "seat": { "at": [dx,dy], "approach": [dx,dy], "face": "right" }   // 책상 종류만
}
```
- 자리 좌표를 책상마다 따로 쓰지 않고 **종류에 한 번** 적어 두면 책상 12개의 자리가 자동으로 나온다(관제 판단 — 손으로 찍는 좌표 수를 줄여 실수를 줄인다).
- 좌우 대칭으로 놓을 때는 오브젝트에 `"flipX": true` — footprint·seat 의 dx 도 뒤집힌다.
- **footprint 는 그림에서 나오지 않는다**(그림 시험 확인). 사람이 점검표를 보며 `kinds` 에 적는다. 그림 시험 보고서가 말한 「config.json 의 표」 와 같은 취지이며, 이 문서는 장면 데이터(`scene.json`)에 둔다.
- `depth: "floor"` = 바닥에 깔린 평면(러그 대안, §4.7). z 는 모든 캐릭터보다 아래(`zBase - 1`), `blocks: false`.

### 4.4 `objects` — 놓인 것
```
{ "id": "desk-3", "kind": "desk", "at": [x, y], "flipX": false }
```
- `at` = 그 종류의 `anchor` 가 방에서 놓이는 점. footprint 는 `at` 기준으로 옮겨서 쓴다.
- 필요하면 `footprint`·`blocks`·`depth` 를 오브젝트에서 덮어쓸 수 있다(예외용).
- `id` 는 방 안에서 유일.

### 4.5 자리와 특별한 점
- **책상 자리 `seats`**: 책상 오브젝트 id 순서 목록 `["desk-1", …]`. 자리 i = 그 책상 종류의 `seat` 를 책상 위치로 옮긴 것. 목록 순서가 배정 순서(지금처럼 작은 번호부터).
- **자리 = 책상 뒤** (관제 판단, 2026-10-28 §17 로 고침): 캐릭터는 책상 **뒤**(화면에서 더 먼 쪽)에서 화면을 본다. 책상이 다리를 가린다. 자리에 있는 동안은 **앉은 자세**(§17)이고, 의자는 캐릭터 **뒤**에 놓인 별도 오브젝트다(등받이가 어깨 뒤로 보임). `at` 은 선 자세로 일어설 때의 발 위치, `sitAt`(§17.3)은 앉은 그림의 바닥 가운데 위치다.
- **얼마나 보이나** — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 그림 시험에서 책상 그림 높이는 약 56px, 캐릭터는 64px 이라 책상 뒤 캐릭터는 대부분 가려진다. 발 y 가 책상 footprint 뒤쪽 선보다 d px 뒤면 머리·어깨가 대략 (8 + d)px 보인다. 그래서 `seat.at` 의 dy 는 **d = 20~24px**(머리·어깨 28~32px 보임)로 정하고 점검표에서 확인한다.
- **도착점과 진입점**: 자리처럼 가구에 바짝 붙은 점(`at`)은 막힌 칸 안일 수 있으므로, 경로는 항상 걸을 수 있는 `approach` 까지 찾고 마지막 한 걸음(approach → at)은 직선으로 간다. 검증기가 이 마지막 걸음이 자기 책상·의자 외 가구를 뚫지 않는지 확인한다(§10).
- **팀장 자리 `lead`**: `{ "desk": "lead-desk", "at":[x,y], "approach":[x,y], "face":"left" }` — 보고함 탁자 뒤.
- **보고함 `tray`**: `{ "object": "tray-1", "queue": [[x,y],…] }` — 일을 끝낸 캐릭터가 서는 줄. 지금 `trayPos` 를 대신한다.
  - 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: `queue` 는 **최소 12점**. 끝난 캐릭터 i 가 i < n 이면 `queue[i]`. i ≥ n 이면 `queue[i % n]` 에서 `floor(i / n)` 줄만큼 `nav.trayRowPx`(28px — 옛 `ui.trayRowPx` 14 는 겹쳐 서는 값이라 간격 24px 이상으로 올림) 위로 올린 점을 계산하고, 가장 가까운 열린 칸에 붙인다(옛 `trayPos` 가 줄을 늘리던 방식과 같다). 그래서 13명 이상이 끝나도 같은 점에 겹쳐 서지 않는다.
- **대기점 `idle`**: 책상이 다 찼을 때 먼저 쓰는 통로 점. 최소 6점, 소파 앞 자리 포함 가능 (관제 판단). 각 점은 `{ "at":[x,y], "face":"left|right" }`.
- **경계 여백** — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: `door.at`·`queue`·`idle`·`overflow` 점과 모든 `approach` 는 `walkable` 경계에서 `inflatePx` 이상 안쪽에 둔다(옛 `entrance` 좌표 일부는 벽에 붙어 있어 그대로 옮기지 않는다). 검증기 §10.1 의 1단계가 확인한다.

### 4.6 넘침 (관제 판단)
- 배정 순서: `seats` → `idle` → `overflow`(최소 8점, 방 가장자리 쪽 넓은 바닥).
- 그것도 다 차면 `overflow` 점을 다시 돌며 고리 r 마다 `nav.overflowRing` px 씩 비킨 점을 쓰고, **가장 가까운 걸을 수 있는 칸으로 붙인다**(§6.3 「닿을 수 없는 목표」 와 같은 규칙). 지금의 `ui.overflowShifts` 표와 `overflowMarginPx` 는 삭제.
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 「비킨다」 의 방향 = **방 중심(`size` 의 가운데)에서 그 점으로 향하는 방향**(바깥쪽). 바깥이 벽이면 붙이기 단계가 가장 가까운 열린 칸으로 되돌린다.
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 붙이기에는 격자가 필요하므로, 첫 그리기(§6.6)에 넘침 점이 있는 층이면 그 디자인의 격자를 그때 한 번 굽는다. 굽기만 하고 길찾기는 하지 않으므로 「첫 그리기에서 길찾기 0회」 는 그대로다.
- 한 층 30명 이상은 지금까지 관찰된 적이 없으므로 그 이상의 배치 품질은 따지지 않는다.

### 4.7 방마다 오브젝트 (지금 그림 실측 + 그림 시험 반영)

「구현자 판단 → 이렇게 정함(제어 세션 결정)」 — 무엇을 스프라이트로, 무엇을 껍데기로:
- **스프라이트 = 바닥에 홀로 선 가구만**: 책상·의자·탁자·소파·안락의자·화분·스탠드 조명·홀로 선 장·바 테이블·지구본 등.
- **껍데기 = 벽에 딱 붙은 책장·장·사다리**: 그림 시험에서 「벽 책장 유지」 를 프롬프트에 넣었는데도 벽 책장·스탠드가 지워졌다. 그래서 껍데기 프롬프트는 이들을 **벽에 평면으로 그려 넣게** 하고(§9.2 프롬프트), 길 막힘은 그 앞 바닥에 `blocked` 다각형(벽 앞 띠)으로 준다. 캐릭터는 항상 그 앞에 서므로 앞뒤가 깨지지 않는다. 좌우 벽 방향 변형 스프라이트가 필요 없어 그림 호출도 준다. 껍데기가 그래도 지우면 그 방만 「벽 방향 스프라이트 1장 추가」 로 되돌린다.
- **방마다 따로 뽑는다**: 책상·의자·화분도 4개 방 공통으로 재사용하지 않는다. 그림 시험 보고서가 「화풍이 다른 방(library·greenhouse)은 자체 소품이 필요」 하다고 했고, 같은 방 안에서도 한 번의 호출로 뽑은 묶음이 팔레트가 가장 잘 맞는다.

## 5. 앞뒤 규칙 (깊이)

### 5.1 기본 규칙 (관제 판단)
- 앞뒤는 **바닥 위 y** 로 정한다. 큰 y = 화면 앞.
  - 오브젝트의 깊이 = footprint 의 **가장 앞쪽 y**(최댓값).
  - 캐릭터의 깊이 = **발 y**(지금 `translate` 의 y 와 같다).
- `z-index`: 오브젝트 `zBase + 2·round(깊이)`, 캐릭터 `zBase + 2·round(발 y) + 1`. 같은 y 면 캐릭터가 앞(발이 footprint 앞선 위에 있으면 그 물건 앞에 서 있는 것이므로).
- 자리 점은 책상 footprint 뒤쪽 선보다 뒤(작은 y)에 오도록 검증하므로, 자리에 선 캐릭터는 항상 책상보다 뒤로 그려진다.
- 의자는 캐릭터 뒤: 의자 footprint 의 앞쪽 y ≤ 자리 `at`.y − 2 로 놓는다(검증 §10.1 의 5단계). 「구현자 판단 → 이렇게 정함(제어 세션 결정)」
- 층 고정 순서: 껍데기(무대 배경) < `floor` 평면(`zBase - 1`) < 오브젝트·캐릭터(zBase~) < `front.png`(`frontZ`) < 이름표·말풍선 층(8000) < 화이트보드·표지(9000). 지금의 8000/9000 은 그대로.
- 겹침 없음 확인: 가장 큰 오브젝트·캐릭터 z ≈ 1000 + 2×576 + 1 = 2153 < 7000(`frontZ`) < 8000 < 9000.

### 5.2 넓은 오브젝트 — 세로 띠로 쪼갠다
- 문제: 대각선 책상(lounge)이나 옆벽을 따라 놓인 긴 장은 앞쪽 선의 y 가 좌우로 크게 변한다. 값 하나로 정하면 그 물건의 「얕은 쪽」 앞에 선 캐릭터가 뒤로 숨는다.
- 규칙: footprint 앞쪽 선의 y 변화가 `sliceTolerancePx` 를 넘는 오브젝트는 `sliceWidthPx` 폭의 **세로 띠**로 나눈다. 띠마다 깊이 = 그 띠의 x 범위 안 footprint 최댓값 y. 화면에서는 띠 하나 = 노드 하나(같은 아틀라스, `background-position` 만 다름).
- footprint 가 없는 띠(나뭇잎·모니터가 옆으로 삐져나온 부분)는 가장 가까운 띠의 깊이를 쓴다.
- 판정은 자동(`depth: "auto"`). 정면 방의 책상처럼 앞선이 수평인 물건은 띠 하나(노드 하나).
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: `fitFloors` 가 층 전체에 비정수 `zoom` 을 걸어 띠 사이에 머리카락 틈이 보일 수 있으므로, 띠는 오른쪽으로 `sliceOverlapPx`(1px) 겹치게 만든다(겹친 1px 은 다음 띠가 덮는다). `flipX` 오브젝트는 그림을 뒤집은 뒤의 화면 x 로 띠를 자르고 깊이를 계산한다(아틀라스 x 와 화면 x 가 반대).
- 업계 표준인 「오브젝트 쌍 비교로 그리기 순서 정렬(토폴로지 정렬)」 은 매 걸음 재정렬이 필요해 버렸다. 띠 방식은 오브젝트 z 가 고정되고 캐릭터 z 만 바뀌므로 화면이 할 일이 거의 없다.

### 5.3 키 큰 물건 · 벽 물건 · 머리 위 물건
- 벽에 붙은 키 큰 물건(책장·장)은 껍데기에 평면으로 둔다(§4.7). 그 앞 바닥은 `blocked` 띠로 막는다. 캐릭터는 항상 그 앞이라 앞뒤가 맞다.
- 껍데기가 지워서 스프라이트로 되돌린 벽 물건만 footprint 를 벽 앞 바닥에 두고, 옆벽을 따라 비스듬하면 §5.2 띠로 처리한다.
- 홀로 선 키 큰 물건(스탠드 조명·큰 화분): footprint = 밑동만. 뒤를 지나는 캐릭터는 밑동 y 보다 작으므로 물건 뒤로 그려지고, 머리는 잎 사이로 보인다(맞는 모습 — 그림 시험의 `check.png` 오른쪽 화분 앞 캐릭터로 앞쪽 경우를 확인).
- 걷는 바닥 **위에 떠 있는** 물건(lounge 펜던트 조명 등): `depth: "overhead"` → `frontZ - 1`, `blocks: false`. 바닥 위에 그림자만 있으면 그림자는 껍데기.
- 벽에만 붙은 것(창·액자·화이트보드·벽등)은 오브젝트로 만들지 않는다(껍데기).

### 5.4 말풍선·이름표
- 말풍선을 이름표와 같은 위층(`.agt`, 지금 z 8000)으로 옮긴다 (관제 판단). 지금은 말풍선이 캐릭터 노드 안에 있어, 키 큰 물건 뒤에 서면 가려진다. `.agt` 는 이미 별도 위층이므로 기존 구조와 맞는다.

## 6. 길찾기와 걷기

### 6.1 격자 굽기 (관제 판단: 격자 A*, 브라우저에서)
- 디자인마다 한 번, **처음 걷기가 필요할 때**(또는 넘침 점 붙이기가 필요한 첫 그리기, §4.6) 굽고 페이지가 살아 있는 동안 재사용한다(최대 4개).
- 칸 크기 `cellPx` 8 → 1024×576 방은 128×72 = 9,216칸(4 로 내리면 36,864칸, §4.8).
- 칸 중심이 `walkable` 합집합 안 **그리고** 어떤 막는 footprint·`blocked` 다각형과도 거리 `inflatePx`(캐릭터 발 반지름 12px — 그림자 타원 폭 32px 의 대략 절반 이상) 이내가 아니면 걸을 수 있다. 바깥 경계에서도 같은 거리만큼 떨어진다.
- 계산: 다각형마다 경계상자로 거른 뒤 칸 중심–다각형 거리. 방 하나 수 ms 수준 예상(빌더가 실측).
- 굽는 코드는 DOM 없는 순수 모듈(예: `web/nav.mjs`)로 둬서 브라우저·Node 시험·검증기가 **같은 코드**를 쓴다. `server/http.mjs` 가 이미 `.mjs` 를 `text/javascript` 로 내보내므로 브라우저에서 모듈로 불러올 수 있다.

### 6.2 경로 찾기
- 8방향 A*, 대각선 비용 √2, 옥타일 거리 휴리스틱. 막힌 칸 모서리를 대각선으로 스치는 이동 금지(두 옆 칸이 모두 열려야 대각선 허용).
- **경로 다듬기**: 시작점에서 보이는(가시선) 가장 먼 경로점으로 건너뛰는 끌어당기기 방식. 가시선 검사는 선분이 지나는 모든 칸이 열려 있는지(슈퍼커버 격자 순회). 결과는 꺾임 몇 개의 꺾은선.
- 같은 방향으로 이어지는 선분은 하나로 합친다(이음매 끊김 줄이기).
- **경로 캐시**: `디자인|시작 칸|목표 칸` → 꺾은선, 페이지 전체 LRU `pathCache` 개. 자리·문·보고함이 고정이라 같은 길이 자주 반복된다.
- 길찾기는 **걷기를 시작할 때만** 돈다. 가만히 있을 때 계산 0.

### 6.3 닿을 수 없을 때
- 시작점이 막힌 칸이면(자리에 붙어 있다가 떠날 때): 먼저 그 점의 `approach` 로 직선 한 걸음, 없으면 가장 가까운 열린 칸으로.
- 목표 칸이 막혀 있으면: `snapRadiusCells` 안에서 가장 가까운 열린 칸(너비 우선 탐색)으로 바꾼다.
- 그래도 길이 없으면: 흐려졌다가 목표에 나타난다(순간이동, 지금 `enter-in` 페이드 재사용). 콘솔 경고 한 번, 디버그 겹침(§8)에 빨간 표시. 검증기(§10)가 출하 장면에서는 이런 경우가 없음을 보장하므로 런타임에는 안전장치일 뿐이다.

### 6.4 걷기 (관제 판단: 선분마다 CSS 트랜지션 이어 붙이기)
- 꺾은선을 선분 목록으로 받고, 한 선분 = `transform: translate()` 트랜지션 하나. `transitionend` 에서 다음 선분을 건다. `requestAnimationFrame`·캔버스 없음.
- 각 선분 시간 = 길이 ÷ 속도(150px/s, `linear`). 전체 걷기가 `WALK_MIN_MS` 보다 짧으면 마지막 선분을 늘린다.
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 길이 1px 미만 선분(자르기에서 생긴 조각 포함)은 트랜지션을 걸지 않고 건너뛴다. 값이 거의 안 바뀌면 `transitionend` 가 오지 않아 이어 붙이기가 멈추기 때문이다(지금 `walkTo` 의 `dist < 1` 처리와 같다).
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 웹 애니메이션 API(`element.animate()`)는 쓰지 않는다. 규칙 위반은 아니지만, 지금의 `body.paused` 규칙(`transition: none !important`)과 맞물리는 것은 트랜지션이고, 애니메이션은 따로 `finish()` 처리가 필요해 멈춤 경로가 둘이 된다.
- **뒤집기**: 선분마다 dx < −1 이면 왼쪽, dx > 1 이면 오른쪽, 그 사이면 이전 방향 유지. 도착하면 그 점의 `face` 로.
- **z 갱신**: 선분을 미리 **깊이선에서 자른다** — 그 선분의 x 범위와 겹치는 오브젝트(또는 띠)의 깊이 y 를 선분이 가로지르면 그 지점에서 나눈다. 잘린 조각마다 z 는 조각 가운데 y 기준으로 조각을 시작할 때 한 번 설정. 그래서 걷는 도중 z 는 정확히 가구를 지날 때만 바뀐다.
  - 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 「x 범위가 겹친다」 판정은 오브젝트(띠)의 x 범위를 양쪽으로 `pickMarginPx`(캐릭터 반폭 22px)만큼 넓혀서 한다. 가장자리를 스칠 때 몸 절반이 몇 px 동안 앞뒤가 어긋나는 것을 막는다.
- 이름표·말풍선 층(`.agt`)은 같은 선분·같은 시간으로 함께 움직인다(지금 방식 그대로).
- **세대 번호**: 캐릭터마다 걷기 세대 번호를 두고, 이전 세대의 `transitionend`/`transitioncancel` 은 무시한다. 마지막 선분이 끝났을 때만 지금의 `settle`(도착, 완료면 점프) 이 돈다.

### 6.5 멈춤·다시 시작·목표 바뀜
- **탭 가림(pause)**: 지금 `body.paused` 가 `transition: none !important` 로 트랜지션을 꺼서 진행 중 선분이 끝점으로 튄다. 그 규칙 위에 더해 걷는 캐릭터는 모두 **최종 목표로 바로 옮기고**(최종 z·방향 적용) 이어 붙이기를 끊는다 (관제 판단). 보이지 않는 동안 일을 하지 않기 위해서다.
- **다시 보임(resume)**: 남은 걷기를 되살리지 않는다. 새 상태에서 목표가 바뀐 캐릭터만 지금 위치에서 새로 길을 찾는다.
- **걷는 중 목표 바뀜**: 지금 위치를 `getComputedStyle(...).transform` 으로 한 번 읽고(이때만 읽음), 세대를 올려 이전 걷기를 끊고, 그 점에서 새 경로로 시작.
- **캐릭터끼리 피하기 없음**. 단 도착점 배정이 서버에서 겹치지 않게 되므로(자리·대기점·넘침 점·보고함 줄 모두 서로 24px 이상 떨어지도록 검증, 보고함 줄 넘침은 §4.5 줄 올리기) 서 있을 때는 겹치지 않는다. 걷는 도중 스치는 것은 허용.

### 6.6 등장·완료·첫 그리기
- 등장: `door.at` 에서 페이드인 후 경로로 자리까지(지금 「문에서 걸어 들어온다」 와 같고, 직선만 경로로 바뀜).
- 완료: 보고함 줄(`tray.queue`)로 경로 걷기 → 도착 후 점프·흐려짐(지금과 같음).
- 페이지를 처음 열 때 이미 있던 캐릭터는 지금처럼 걷지 않고 바로 놓인다(첫 그리기에서 길찾기 0회, 격자 굽기는 넘침 점이 있을 때만 §4.6).

## 7. 서버 바꿀 곳

### 7.1 자리 배정 (`server/office.mjs` `#allocSlot`)
- `this.cfg.layouts[design]` 대신 읽어 둔 장면에서 `seats` → `idle` → `overflow` 순으로 가장 작은 빈 번호를 준다(번호 재사용 규칙은 지금 `usedSlots` 그대로).
- 돌려주는 자리 모양: `{ i, kind: "seat"|"idle"|"overflow", ref, x, y, approach: [x,y] | null, face, ring }`
  - `ref` = 책상 id 또는 대기점 번호, `ring` = 넘침 고리 번호(0 = 첫 바퀴). 고리 비킴과 가장 가까운 열린 칸 붙이기는 **화면이 한다**(격자는 화면에만 있다). 서버는 격자를 굽지 않는다.
- 팀장 자리·보고함 줄도 장면에서 읽는다(지금 `layout.lead`, `trayPos` 대체).
- 디자인 고르기(`#pickDesign`, `designOrder`) 는 그대로.

### 7.2 API
- `/api/ui`: `layouts` 대신 `scenes`(디자인 → 검사 통과한 `scene.json` 내용 + 그림 URL). `spriteHeight` 등 나머지 그대로. 장면 데이터에 개인정보 없음.
- 스냅숏 `agents[].slot` 은 위 7.1 모양. 층 단위 필드는 그대로.
- 정적 파일: `assets/scenes/**.png` 는 지금 `assets` 정적 제공·이미지 캐시 헤더를 그대로 탄다.

### 7.3 설정 검사 (`server/config.mjs`)
- 시작할 때 `designOrder` 의 디자인마다 `scene.json` 존재·형식(§10.1 1단계)을 검사하고, 실패하면 그 디자인을 **옛 배치(이전 기간, §11) 또는 시작 거부**. 도달 가능성 같은 무거운 검사는 서버 시작 때 하지 않는다(시험·검증기 몫).
- 「구현자 판단 → 이렇게 정함(제어 세션 결정)」: 「`rect` 가 아틀라스 안」 검사는 `objects.png` 의 PNG 머리(IHDR, 앞 24바이트)에서 폭·높이만 읽어서 한다. 의존성 없이 몇 줄이고 그림을 해독하지 않는다.


### 8.2 디버그 겹침 `?debug=nav`

### 9.2 프롬프트 (시험에서 통한 문장 + 본작업 변경점)

**껍데기 — 시험에서 통한 원문**

본작업 변경점 — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」:
- 참고 그림은 그 방의 `assets/floors/<design>.png` 를 `-i` 로 넣는다. 비율 문구는 방에 맞게(studio2 「2:1」, 나머지 「16:9」).

- greenhouse 는 「keep the door frame」 을 넣는다.

**스프라이트 시트 — 시험에서 통한 원문(물건 목록 부분만 방마다 바뀜)**

Layout: one row of 4 objects with wide empty gaps, each object alone, fully separated, on a flat solid #FF00FF magenta background (no shadow on the floor, no floor, no glow). Objects left to right: 1) ... 4) ... Do not use magenta anywhere inside the objects. Canvas 2:1 wide. Save as sheet.png ..."

본작업 변경점 — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」:
- **한 장에 6~8개**(「two rows of 3-4 objects」)를 먼저 시도한다. 시험 스프라이트가 필요 크기의 약 5배로 나왔으므로 줄여도 해상도가 남는다. 물건이 붙거나 잘리면 그 방은 시험 그대로 **한 줄 4개**로 돌아간다. 예상 호출 수: 방당 껍데기 1 + 시트 2(4개씩이면 2~3) + 재시도 1~2 → 4개 방 합쳐 약 12~20회.
- 책상은 「**desk seen from the front, the back of the monitor faces the viewer, no chair**」 로 그린다(캐릭터가 책상 뒤에서 화면을 보는 모습, §4.5). 이 방향은 시험하지 않았으므로 studio2 첫 시트의 첫 확인 항목이다. 두 번 시도해도 모니터 뒷면이 안 나오면 시험처럼 앞면 모니터 책상을 쓰고 자리 규칙(책상 뒤에 서기)은 그대로 둔다(`check.png` 의 모습).
- 의자는 「office chair seen from behind, facing away from the viewer」(캐릭터 뒤에 놓임).
- 같은 방의 시트는 같은 참고 그림을 넣고 연달아 뽑는다(호출 사이 팔레트 흔들림 줄이기).

### 9.3 후처리 (`art/snap.py` 에 `shell`·`obj` 모드 추가, 절대경로)
1. **껍데기**: LANCZOS 로 `size` 까지 축소(지금 `bg` 모드와 같은 방식).
2. **키잉**: 픽셀이 R > 150, B > 150, G < R − 70, G < B − 70 이면 배경(알파 0). 시험 시트에서 84% 가 배경으로 빠졌다.
3. **가장자리**: 1px 깎기(erosion) + 분홍 번짐 줄이기(가장자리 픽셀의 R·B 를 G 쪽으로 당김).
4. **나누기·잘라내기**: 비어 있는 세로 열(2줄 시트는 가로 행도)로 물건을 나누고 투명 여백을 잘라낸다.
5. **종류별 배율 축소**: 프리멀티플라이드 BOX 축소 → 알파 임계 127(알파 0/255). 배율은 **종류마다** 따로(§9.4). 이전 초안의 「모음 전체를 같은 배율」 은 시험에서 소파가 약 30% 작게 나와 버렸다.
6. **팔레트 줄이기**: 「구현자 판단 → 이렇게 정함(제어 세션 결정)」 물건마다 약 24색으로 양자화(알파는 그대로). 축소로 흐려진 픽셀 격자를 되살린다. 화면에서는 `image-rendering: pixelated`.
7. **아틀라스 묶기**: 잘린 그림을 `objects.png` 한 장으로 묶고 `kinds[*].rect` 를 자동 기록. `anchor`·`footprint`·`seat` 는 사람이(또는 빌더가) 점검표를 보며 적는다(§10.3).
8. **앞 덮개**: 껍데기에서 `frontMask` 다각형으로 잘라 `front.png` 생성(문틈 제외, §4.7).

### 9.4 크기 맞추기 — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」
- 「구현자 판단 → 이렇게 정함(제어 세션 결정, 2026-10-28 계획서)」: 방 작업을 병렬로 돌리기 위해 파일은 방마다 하나 `art/scenes/<design>.json` 으로 나눈다(아래 「`art/scenes.json`」 은 이 파일들을 말한다).
- `art/scenes.json` 에 방·종류마다 **목표 크기 표**(목표 폭 px, 또는 목표 높이 px)를 둔다. 배율 = 목표 ÷ 잘린 그림 크기.
- 기준은 지금 그림의 책상 폭(studio2 ≈ 83px). 지금 그림에 있는 종류(의자·화분·소파·탁자 등)는 지금 그림에서 잰 크기를 그대로 목표로 쓴다.
- 지금 그림에 없는 종류(커피 머신·지구본 등)는 캐릭터 64px 기준 상대 크기로 정한다(예: 지구본 스탠드 ≈ 캐릭터 허리 높이).
- 점검표(§10.2)에서 캐릭터 64px 과 나란히 보고 고친다.

### 9.5 걸을 수 있는 바닥 — 「구현자 판단 → 이렇게 정함(제어 세션 결정)」
- 껍데기 바닥 윤곽이 원본과 1px 이내로 같았으므로, `walkable` 은 **원본 그림의 바닥 윤곽을 한 번 따라 그려** 만든다(꼭짓점 몇 개). 16:9 방 3개(lounge·library·greenhouse)는 시험하지 않았으므로 방마다 같은 방법(배경 아닌 마스크 IoU)으로 **0.9 이상**인지 확인하고, 못 미치면 그 방 껍데기를 1~2회 다시 뽑는다.

### 9.6 lounge 와 후퇴안
- 시험의 스프라이트는 「정면에 가까운 사선」 까지만 나왔고 진짜 대각선 아이소 각도는 못 냈다. lounge 의 대각선 책상·의자(§4.7)와 띠 분할(§5.2)은 이 각도에 기대므로 lounge 에서 먼저 시트 1장으로 시험한다.
- 실패하면 (1) 그 종류만 방식 B(지금 lounge 그림에서 다각형 마스크로 오려 쓰기)로 시도하고, (2) 그래도 안 되면 §18 의 2번을 묻는다.

### 9.7 공통
- Codex 「모델 혼잡」 오류 시 `~/.codex/generated_images/<세션>/` 에서 가져온다(본 설계서 §6.2). 그 외 `~/.codex` 파일은 열지 않는다.
- 프롬프트·목표 크기 표는 `art/scenes.json`(새 파일)에 남겨 다시 뽑을 수 있게 한다. 원본은 저장소 밖 임시 폴더, 결과만 `assets/scenes/`.
- 그림 생성은 헤드리스로만(창을 띄우지 않는다). 호출 수는 §18 의 3번 기본값 안에서.

## 10. 장면 작성과 검증

### 10.1 검증기 (관제 판단: `scripts/check-scenes.mjs`, `npm test` 에도 포함)
같은 `nav.mjs`·`depth.mjs` 를 써서 디자인마다:
1. **형식**: 필수 필드, id 유일, `kind` 존재, `rect` 가 아틀라스 안(IHDR 크기, §7.3), 다각형 꼭짓점 3개 이상, 모든 좌표가 `size` 안, `seats` 가 책상 오브젝트를 가리킴, 책상 자리 12개(지금 수와 같게), `idle` ≥ 6, `overflow` ≥ 8, `tray.queue` ≥ 12, 경계 여백(§4.5 — 문·줄·대기·넘침·`approach` 점이 `walkable` 경계에서 `inflatePx` 이상 안쪽).
2. **도달**: `door.at` 에서 출발해 모든 자리 `approach`, 팀장 `approach`, 보고함 줄, 대기점, 넘침 점에 경로가 있다(실패 시 어느 점인지 출력).
3. **마지막 걸음**: approach → at 선분이 자기 책상·의자 외 막는 footprint 를 지나지 않는다.
4. **간격**: 도착점끼리 24px 이상(서 있을 때 겹침 없음).
5. **깊이**: 자리 `at` 의 y 가 그 책상 footprint 뒤쪽 선보다 작다(책상 뒤에 선다). 그 자리 의자 footprint 앞쪽 y ≤ 자리 `at`.y − 2(의자는 캐릭터 뒤). 막는 footprint 끼리 겹치지 않는다.
6. **가림 경고**(실패 아닌 경고): 「구현자 판단 → 이렇게 정함(제어 세션 결정)」 자리·팀장 자리·보고함 줄에 선 캐릭터의 **얼굴 영역(그림 위쪽 `faceTopPx` 24px)** 을 더 앞 깊이의 오브젝트 그림 상자가 가리면 경고. 이전 초안의 「상자 절반 초과」 는 책상 뒤 자리 12개가 전부 걸리므로(설계상 다리는 가려져야 함) 버렸다.
7. **앞 덮개**: `door.at`, 모든 `approach`, 보고함 줄 점이 `frontMask` 다각형 안에 있지 않다. PNG 를 해독하지 않고 다각형으로 검사한다.
8. **활동 지점**(§16.4): 방마다 `spots` 4~8개, id 유일, 각 `at`·`pair` 가 경계 여백 안쪽, **모든 자리 `approach` 와 팀장 `approach` 에서 경로가 있다**, 다른 도착점(자리 `at`·`visit`·대기·넘침·보고함 줄·팀장 자리)과 24px 이상 떨어진다. 책상 종류의 `seat.visit` 도 같은 검사.
9. **앉은 자세 보임**(§17.3): 자리·팀장 자리마다 앉은 그림 윗변(`sitAt.y − sitHeight`)이 그 책상 그림 윗변보다 `depth.seatShowPx` 이상 위에 있다(머리·어깨가 책상 위로 보임). `sitAt` 이 책상 footprint 뒤쪽 선보다 뒤, 의자 footprint 앞쪽 y ≤ `sitAt.y − 2`.

### 10.2 Pillow 점검표 (`art/scene_sheet.py` → `art/scenes-check/<design>.png`)
- 껍데기 + 오브젝트를 깊이 순으로 합성 + 기본 캐릭터 그림을 모든 자리·팀장 자리·보고함 줄에 세운 장면.
- 같은 그림 옆에 겹침판: footprint·걷기 격자·깊이선·점 번호·`frontMask`(§8.2 와 같은 정보).
- 깊이 시험판: 캐릭터를 책상 앞·뒤, 큰 화분 앞·뒤, lounge 대각선 책상 양 끝 앞·뒤에 세운 작은 칸들.
- 옛 그림과 새 장면을 위아래로 붙인 비교판(그림 시험의 `compare.png` 와 같은 모양) — §18 의 1번 확인에 쓴다.
- 헤드리스로만 만든다(창을 띄우지 않는다). 지금 `art/floors-check/` 와 같은 쓰임.

### 10.3 좌표 만드는 순서
1. 원본 바닥 윤곽을 따라 `walkable` 다각형을 그리고(§9.5), 벽 앞 껍데기 책장 띠를 `blocked` 로 적는다.
2. 종류마다 `anchor`·`footprint`·`seat` 를 한 번 적는다(`seat.at` dy 는 §4.5).
3. 오브젝트 `at` 을 놓는다 — 책상 줄은 지금 `layouts.desks` 좌표를 출발점으로 쓰되 줄 간격 90px 이상(§4.8).
4. `board`·`reports`·`sign` 을 새 껍데기에서 잰다(§4.2).
5. 검증기 → 점검표 → 고치기를 통과할 때까지 반복.

## 16. 근무 중 생활 움직임

### 16.1 사용자 요청 (원문, 2026-10-28)
> 「그리고 캐릭터가 전혀 움직이질 않네 실제 회사에 근무하는 사람 처럼 종종 움직이기도 하면 좋겠는데 너무 정적이야」

지금은 캐릭터가 서버가 옮길 때(등장·완료·자리 바뀜)만 움직이고 그 밖에는 자리에 가만히 있다. 아래는 모두 **(관제 판단)** 기본값이며 사용자가 바꾸면 그대로 바뀐다.

### 16.2 어디서 도나 (관제 판단)
- **화면에서만** 돈다. 서버 상태·스냅숏·API 는 바뀌지 않는다(서버는 생활 움직임을 모른다).
- 층마다 `setTimeout` 사슬 **하나**(캐릭터마다 하나가 아니다, `requestAnimationFrame` 아님). 한 번 깰 때 그 층의 캐릭터 중 때가 된 것만 처리하고, 다음 깰 시각 = 가장 이른 예정 시각(최소 `tickMinMs`).
- 탭이 가려지면(`pause`) 모든 층의 타이머를 끊고 나가 있던 캐릭터는 자기 자리로 바로 옮긴다(§6.5 와 같은 규칙). 다시 보이면 예정 시각을 지금부터 새로 뽑는다.
- 캐릭터마다 난수는 `agentId`(팀장은 `sessionId + ":lead"`)로 씨앗을 준 난수열을 쓴다. 그래서 같은 순간에 다 같이 움직이지 않고, 같은 캐릭터는 다시 열어도 같은 박자다.
- `ui.ambient.enabled: false` 면 아무것도 만들지 않는다.

### 16.3 자리 몸짓 (관제 판단)
- 자리에 있는 모두(일하는 중 포함)가 `fidgetEveryMs` 범위마다 짧은 몸짓 하나를 한다: 둘러보기(뒤집었다 되돌리기), 기지개(세로·가로 늘이기), 기대기·자리 고쳐 앉기(몇 px 좌우), 작은 깡총(선 자세에서만).
- 몸짓은 CSS 클래스 하나를 `fidgetMs` 동안 붙였다 떼는 키프레임이다. 지금 상태 연출(`.spr` 의 통통·숨쉬기)과 겹치지 않게 `.body`·`.flip` 층에 건다.
- 앉은 자세(§17)에서는 앉은 변형만 쓴다(기대기, 둘러보기, 팔 뻗기 = 늘이기). 목록은 `ui.ambient.fidgets.seated` / `.standing`.

### 16.4 자리 비우기 — 활동 지점 다녀오기 (관제 판단)
- 장면에 `spots` 목록을 둔다: `{ "id", "kind", "at":[x,y], "face":"left|right", "pair":[x,y]? }`. `kind` 는 `coffee | water | window | shelf | plant | sofa | whiteboard | other`. 방마다 **4~8개**. `at` 은 걸을 수 있는 칸(경계 여백 안쪽)이고 도착하면 `face` 쪽을 본다.
- 책상 종류의 `seat` 에 `visit: [dx,dy]`(동료 책상 옆에 서는 점)를 둔다. 「동료 책상 옆」 은 이 점이다.
- 가끔 일어나(§17 일어서기) 지점까지 길(§6)로 걸어가 `stayMs` 범위만큼 머물고 자기 자리로 돌아와 앉는다.
- 얼마나 자주(`tripEveryMs` — 상태별 범위):
  - 일하는 중(도구 실행) → 드묾
  - 생각 중 → 자주(생각하며 서성임)
  - 대기·멈춤(`idle`·`enter` 도착 후)·응답 없음(`stale`) → 자주
  - 팀장: 세션이 입력을 기다릴 때(`waiting`) `leadTourEveryMs` 마다 자리 찬 책상 `leadTourDesks` 곳의 `visit` 점을 돌거나 화이트보드 지점에 다녀온다.
- 한 층에서 동시에 자리를 비운 캐릭터는 최대 `maxAway` 명.
- 한 지점에는 한 명. 단 `pair` 가 있는 지점에 한 명이 머무는 중이면 `chatChance` 확률로 두 번째가 `pair` 에 와서 둘이 서로 마주 본다(「잡담」).
- 서버가 옮기는 움직임이 **항상 이긴다**: 등장·완료(보고함)·퇴장·자리 바뀜이 오면 나들이를 바로 끊고 지금 위치에서 새 목표로 길을 찾는다. 나가 있는 동안 `working` 이 되면 바로 자리로 돌아간다.
- 옛 배치(장면 없는 디자인, §11 이전 기간)에서는 나들이를 하지 않고 몸짓만 한다.

### 16.5 숫자 (관제 판단 — `config.json` `ui.ambient`, 시작값)
```
"ambient": {
  "enabled": true, "tickMinMs": 1000,
  "firstDelayMs": [3000, 20000],
  "fidgetEveryMs": [8000, 40000], "fidgetMs": 1200,
  "fidgets": { "seated": ["look", "lean", "stretch"], "standing": ["look", "lean", "stretch", "hop"] },
  "tripEveryMs": { "working": [240000, 600000], "thinking": [30000, 90000], "idle": [45000, 150000], "stale": [60000, 180000] },
  "leadTourEveryMs": [40000, 120000], "leadTourDesks": 3,
  "stayMs": [4000, 12000], "maxAway": 2, "chatChance": 0.5
}
```
- `ui` 블록은 이미 `/api/ui` 로 화면에 가므로 API 모양은 늘지 않는다.
- 자원 예산(§2 목표: 평균 한 코어 2% 이하)은 그대로이며 생활 움직임을 켠 상태에서 다시 잰다.

## 17. 앉은 자세

### 17.1 사용자 요청 (원문, 2026-10-28)
> 「또 대각선 정면 앉아 있는 이미지를 구현해야 할거 같은데 일할 때는 앉아 있도록」

사용자가 이 그림용 Codex 호출 **10회**를 따로 승인했다(방 30회와 합쳐 모두 40회). 아래는 모두 **(관제 판단)** 기본값.

### 17.2 그림
- 본 설계서의 「캐릭터마다 그림 한 장, 늘이기·뒤집기·이동만」 규칙을 **그림 두 장**으로 고친다: `assets/sprites/<key>.png`(선 자세, 높이 64px) + `assets/sprites/<key>-sit.png`(앉은 자세).
- 앉은 그림 = 같은 캐릭터·같은 점 화풍·같은 점 크기, **대각선 정면(3/4 앞)** 에서 본 의자에 앉은 모습. 높이는 `sitHeight`(config, 시작값 50px). 의자는 그리지 않는다(장면의 의자 오브젝트가 뒤에 있다).
- 왼쪽을 보는 대각선은 `flipX`(지금 `.flip.left`)로 만든다.
- 17개 역할 + `default` 모두. 한 장에 4~6명씩, 선 자세 그림을 `-i` 참고로 넣어 Codex 로 뽑는다(계획서 Task 6).
- `<key>-sit.png` 가 없으면 선 자세 그림을 그대로 쓴다. 서버가 시작할 때 있는 앉은 그림 목록을 `/api/ui` 의 `sitSprites` 로 넘긴다(없는 그림을 요청해 404 를 내지 않는다).

### 17.3 언제 앉고 언제 서나
- **앉음**: 자기 자리(책상 자리 `kind: "seat"` 또는 팀장 자리)에 도착해 있을 때 — 일하는 중·생각 중·대기·응답 없음(zZ) 모두.
- **섬**: 걷는 동안, 활동 지점에 머무는 동안, 보고함 줄, 등장·퇴장, 대기점(`idle`)·넘침 자리(의자가 없다).
- 일어서기·앉기는 짧은 찌그러짐 전환(CSS 키프레임, 약 200ms) 한 번 뒤에 그림을 바꾼다. 두 그림은 `.spr` 안에 둘 다 두고 클래스로 보이기만 바꾼다(그림 다시 불러오기 없음).
- 앉은 자세의 몸짓은 §16.3 의 앉은 변형만.
- 옛 배치(장면 없는 디자인)에서는 앉지 않는다(의자 오브젝트가 없다).

### 17.4 자리 좌표와 가림
- 책상 종류 `seat` 에 `sitAt: [dx,dy]`(앉은 그림 바닥 가운데)를 더한다. 없으면 `at`. 팀장 자리도 `lead.sitAt`.
- 앉은 캐릭터의 깊이 = `sitAt.y`. 검증기가 `sitAt` 이 책상 footprint 뒤쪽 선보다 뒤이고 의자 앞쪽보다 앞(`의자 앞쪽 y ≤ sitAt.y − 2`)인지 본다. 그래서 그리기 순서는 의자 < 앉은 캐릭터 < 책상.
- 머리·어깨가 책상 위로 보이도록 앉은 그림 윗변이 책상 그림 윗변보다 `depth.seatShowPx`(시작값 28px) 이상 위여야 한다(§10.1 의 9단계). 책상 그림 윗변은 아틀라스 `rect` 높이로 계산하므로 보수적이다.
- 새 숫자: `"sitHeight": 50`(최상위, `spriteHeight` 옆), `depth.seatShowPx: 28`.
